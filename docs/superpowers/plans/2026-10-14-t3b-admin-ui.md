# T3b: Administration UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Lean format: files, interfaces, components, test cases and acceptance criteria per task. Implementers write the code test-first; code appears only where it defines a contract.

**Goal:**
- System admins and project leads do in the browser everything T3a offers over the API: users, ontologies, projects, members, uploads, assignments, progress and exports.
- Annotators and adjudicators land on "My tasks" and open assigned documents only.
- Imported proposals show their tool provenance in the editor.

**Architecture:**
- **Routing:** a hash router without a dependency (index D-p), `frontend/src/app/router.ts`. `App.tsx` keeps the login gate and the session-lost handling. Everything after login renders inside `Shell` by route.
- **Pages:** the editor screen (`CaseScreen`) is reused unchanged behind `#/tasks/:assignment`. The old dashboard with project select, mode chooser and document list is replaced by "My tasks". Admin pages live in `frontend/src/admin/`, one file per page.
- **Shared pieces:** `useJob` (job polling), `ErrorNotice` (code → message table, rendered with `InlineMessage`) and `CodeOnceDialog` (on `ui/Dialog`). `ConfirmDialog` comes from `frontend/src/ui/` (T6a).
- **API:** all calls go through `ApiClient` in `frontend/src/api/client.ts`, with types from the generated OpenAPI file (T3a regenerated it).

**Spec:** `docs/superpowers/specs/2026-10-14-t3-admin-design.md` (A1–A5). T7 I3 display. Index: `docs/superpowers/plans/2026-10-14-t3-t5-t4-index.md`. Backend: `docs/superpowers/plans/2026-10-14-t3a-admin-backend.md`. Builds on T3a and T6a.

**Commit rule:** per task, `npm --prefix frontend run typecheck && npm --prefix frontend test`, plus the Python commit rule when Python files change (Task 11), then one conventional commit without AI attribution.

**Conventions for every page:**
- **Design (T6a, binding):** `DESIGN.md`; pages render inside `AppShell` in compact density; tables are `DataTable`, forms use the `ui/` fields, messages `InlineMessage`, empty lists `EmptyState`; no inline colours and no page-specific colour values. Page keyboard shortcuts register through `useShortcut` with a description.
- **Accessibility:** every control has a visible label; tables use `DataTable` (`<th scope="col">`); dialogs use `ui/Dialog` or `ui/ConfirmDialog` (focus trap, Escape closes, focus returns).
- **Errors:** API errors go through `ErrorNotice`, which looks up `err.code` in `frontend/src/admin/errors.ts` and falls back to the server message.
- **Test ids:** `data-testid` only where a role/label query is ambiguous. Ids named below are the contract for the Playwright specs.

### Task 1: Hash router and app shell (D-p)

**Create** `frontend/src/app/router.ts`, `frontend/src/app/Shell.tsx`, `frontend/tests/router.test.ts`, `frontend/tests/shell.test.tsx`. **Modify** `frontend/src/App.tsx`.

**`router.ts`** (the contract):

```ts
export type Route =
  | { name: "tasks"; project?: string }
  | { name: "task"; assignmentId: number }
  | { name: "me" }
  | { name: "adminUsers" }
  | { name: "adminOntologies" }
  | { name: "projectNew" }
  | { name: "projectSettings"; key: string }
  | { name: "projectDocuments"; key: string }
  | { name: "projectProgress"; key: string }
  | { name: "projectExport"; key: string }
  | { name: "notFound"; hash: string };

export function parseRoute(hash: string): Route;   // "#/projects/a/settings" -> {name: "projectSettings", key: "a"}
export function routeHref(route: Route): string;   // inverse of parseRoute; keys are encodeURIComponent'd
export function useRoute(): Route;                 // subscribes to "hashchange"
export function navigate(route: Route): void;      // sets location.hash
```

- `#/` and the empty hash are `tasks`; `#/?project=k` gives `tasks` with a project filter. `#/tasks/<n>` is `task`.
- Any other hash is `notFound`.
- Later plans add their routes here (index, shared contracts).
- `#/tasks/:assignment` is introduced here, because opening work by assignment is a T3 concern. T5 and T4a extend the page behind it.

**`Shell.tsx`:** built on T6a's `AppShell` (`frontend/src/ui/AppShell.tsx`): its header carries the product name, the breadcrumb and the current user (`current-user`, as before, with "Log out"); the navigation below goes into the `nav` slot. The navigation is built from `CurrentUser` and `ProjectSummary[]`:
- everyone: "My tasks" (`#/`) and "Profile" (`#/me`);
- system admin: "Users", "Ontologies" and "New project";
- per project with `can_manage`: "Settings", "Documents", "Progress" and "Export", grouped under the project name.

`App.tsx`: after login, render `<Shell>` with the page for `useRoute()`. Remove the old dashboard state (project select, mode chooser, document list) and `openPackage`. The `legacy`/session-lost code stays.

**Tests:**
- `router.test.ts`: `parse_and_href_round_trip_every_route` (all route kinds, keys with `-` and `%`); `unknown_hashes_are_notFound`; `the_project_filter_is_read_from_the_query`.
- `shell.test.tsx`:
  - `an_annotator_sees_only_tasks_and_profile`;
  - `an_admin_sees_users_ontologies_and_new_project`;
  - `a_lead_sees_the_project_pages_of_managed_projects_only`;

**Not-found and no-access page:** `frontend/src/app/NotFound.tsx` renders "This page does not exist." or "You do not have access to this page." with a link to My tasks. It is used for `notFound` routes and for 403/404 answers of page loads.

### Task 2: My tasks and opening work by assignment

**Create** `frontend/src/tasks/MyTasks.tsx`, `frontend/src/tasks/TaskEditor.tsx`, `frontend/tests/myTasks.test.tsx`, `frontend/tests/taskEditor.test.tsx`. **Modify** `frontend/src/api/client.ts`, `frontend/src/app/CaseNavigation.tsx`, `frontend/src/app/caseOrder.ts`, `frontend/browser/helpers.ts`. **Delete** the dashboard tests replaced here: `frontend/tests/dashboard.test.tsx`, `frontend/tests/projectModes.test.tsx` (T2c) and the dashboard parts of `firstRun.test.tsx` and `workflow-regressions.test.tsx`. Port each behaviour that still exists to the new tests (list the deletions in the commit message).

**Client:**
- `listMyTasks(): Promise<TaskSummary[]>` (`GET /me/tasks`);
- `openAssignment(id): Promise<AssignmentWorkspace>` (`POST /assignments/{id}/open`). `AssignmentWorkspace` is the workspace view plus `assignment` and `read_only`.

**`MyTasks`:**
- **Filter:** a project filter `<select id="project-select">` with "All projects" plus one option per project with tasks. It is kept under this id for the Playwright helpers.
- **Table:** one row per task: document, language, task ("Annotate", "Review"), status, last change, and an "Open" button. `data-testid="task-row"` per row.
- **Order:** as returned by the server (T3a: reopened, in progress, open, submitted).
- **Empty state:**
  - for a user without tasks: "No documents are assigned to you yet.";
  - for a lead, in addition, a link "Assign documents" to the project's documents page.
- **Counts** above the table: open, in progress, submitted.

**`TaskEditor`** (`#/tasks/:assignmentId`):
- It calls `openAssignment`, then renders `CaseScreen` with the returned workspace. The mode comes from the assignment; there is no chooser.
- `read_only: true` disables every editing control and shows the notice "Submitted. The project lead can reopen it for changes." (Q17).
- **Case navigation** (next and previous) moves through the user's tasks of the same project and task, in My-tasks order. `caseOrder.ts` gets `orderTasks(tasks, current) -> {previous?: number, next?: number}`.
- **After submit** the "Case submitted" dialog offers "Next task" and "Back to my tasks".
- **Errors:**
  - `ASSIGNMENT_REQUIRED` and `DOCUMENT_NOT_FOUND` show "This task is no longer assigned to you." with a link back;
  - `ASSIGNMENT_SUBMITTED` reloads in read-only mode.

**Playwright helpers** (`frontend/browser/helpers.ts`; signatures unchanged so the existing specs keep working):
- `importPackage(page, query, projectKey, annotator)`: log in as `annotator` (the browser server grants membership and assignments, T3a Task 10), go to `#/?project=<projectKey>`;
- `openCase(page, _opts)`: clicks "Open" in the first `task-row`.

### Task 7: Documents page with upload preview and commit

**Create** `frontend/src/admin/DocumentsPage.tsx`, `frontend/src/admin/UploadPanel.tsx`, `frontend/src/admin/UploadPreview.tsx`, `frontend/src/admin/useJob.ts`, `frontend/tests/uploadPanel.test.tsx`, `frontend/tests/useJob.test.ts`, `frontend/tests/documentsPage.test.tsx`. **Modify** `client.ts` (`listProjectDocuments` with filters, `createUpload`, `getUpload`, `commitUpload`, `discardUpload`, `listUploads`, `getJob`).

**`useJob(jobId | null, {intervalMs = 1000}) -> {job, error}`:**
- polls `getJob` until `succeeded` or `failed`;
- stops on unmount and on a job id change;
- backs off to 5 s after 30 s;
- has no global state.

**`DocumentsPage`** (`#/projects/:key/documents`):
- **Filters:** language, status (`unassigned`, open, in progress, submitted, reopened) and an id prefix, kept in the URL query.
- **Table:** a checkbox per row and a "select all visible" checkbox; document id, language, assignees (`pseudonym: task status`). `data-testid="document-row"` per row.
- **Toolbar** with the selection count; its actions belong to Task 8.
- An "Upload documents" button opens `UploadPanel`.

**`UploadPanel`:**
- **Choice:** "T1 bundle (.zip or .json)" or "Plain text (.txt or .zip of .txt)". For text, a language select limited to the project's languages, if any.
- **Upload:** files are sent with `createUpload`, then `useJob` follows the preview job. A spinner text "Checking …" is shown.
- **Discard:** "Discard" is available in `ready` and `invalid`.

**`UploadPreview`** renders `UploadView.preview`:
- **Summary:** documents to add, unchanged, documents only (O2), proposal sets, proposals, and texts changed by normalisation (A1).
- **Errors** (blocking, in an alert): collisions with the existing and new hash prefix, validation errors grouped by code with unit and annotation id, missing tool provenance (`T1_TOOL_PROVENANCE`), pin mismatches.
- **Warnings:** duplicates by text (`document_id` and the ids with the same text), ontospan warnings.
- **Proposal sets:**
  - one row per set: document, tool label `name version` plus `model` and `run_id` when present (I3), proposals to import, and refused proposals (O4). A disclosure lists the refused ones with their rule ("discontinuous mention", "hidden axis value");
  - sets already imported are marked "already imported".
- **"Import"** is enabled only when `committable`. It sends `commitUpload(plan_sha256)` and follows the commit job.
  - Success: "Imported N documents and M proposals." and the list reloads.
  - `UPLOAD_STALE`: "The project changed since this preview. Check again." with a "Check again" button, which creates a new upload from the same files still in the input.

**Tests:**
- `useJob.test.ts`: `polls_until_done`; `stops_on_unmount`; `backs_off_after_30_seconds` (fake timers).

## Notes for implementers

- **Where the old dashboard went:** the project select, mode chooser and document list of `App.tsx` are removed in Task 2. T4a's plan mentions removing the mode chooser; after this plan there is none left to remove, so T4a only drops the mode values from the client types.
- **No client-side authorisation logic beyond navigation:** pages render what the API returns. A 403 or 404 shows "You do not have access to this page." The server is the only enforcement (A3).
- **Polling budget:** only `useJob` polls, at most one request per second per open job. My tasks reloads on focus (`visibilitychange`), not on a timer.
- **Large tables:** the documents and progress tables render up to 1 000 rows directly (E12: hundreds to a few thousand documents per project). If the T2e load test or manual testing shows slow rendering, pagination with `?offset=` is a contained follow-up; the API already returns the rows in a stable order.
- **Strings:** all new UI strings are English and kept in the components. The translatable-label mechanism of T5 V1 applies to the review scheme only.
