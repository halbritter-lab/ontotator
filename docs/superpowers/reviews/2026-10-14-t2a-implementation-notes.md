# T2a implementation notes

Deviations from `docs/superpowers/plans/2026-10-14-t2a-postgres-storage.md` found while executing it.
Each entry: task, what the plan said, what was done instead, why.

## Baseline (Task 0)

- Worktree from `main` at `50cee7e`. Baseline: 661 backend tests, 323 frontend tests, all passing.
- `docker version --format '{{.Server.Version}}'` prints the literal template in Git Bash on this machine; `docker version` without `--format` shows the server (Docker Desktop 4.95.0, engine 29.8.2).

## Deviations

- Task 4: `test_even_the_schema_owner_cannot_change_history` ran `TRUNCATE annotation_snapshots` -> runs `TRUNCATE annotation_snapshots CASCADE`, because PostgreSQL rejects a plain truncate of a table referenced by `proposal_annotations` with a foreign-key error before the append-only trigger fires; CASCADE reaches the trigger, which still rejects it.
- Task 4: `tests/pg_harness.py` imported `testcontainers.postgres` -> imports `testcontainers.community.postgres` with a fallback to the old path, because testcontainers 4.15 deprecates the old module with a DeprecationWarning.
- Task 4: `tables.py` declared `type_annotation_map = {...}` -> `type_annotation_map: ClassVar[dict[Any, Any]] = {...}`, because ruff RUF012 rejects the unannotated mutable class attribute.
- Task 4: the plan left `tests/test_review_findings.py::test_fresh_schema_contains_ontology_resources_and_no_legacy_migrations` untouched until Task 8 -> its assertion `not (storage/migrations).exists()` now checks that `storage/migrations` holds no `*.sql` files, because the Alembic environment lives in that directory and the full suite must stay green; the legacy SQLite migrations were `*.sql` files there. Task 8 still deletes the test.
- Task 5 (review fix): `_verify_existing_snapshots` only updated stored copies of a tree walk when the incoming event was longer, and the new project then stored the shorter incoming payload -> it returns `{event_id: longest stored copy}` and `_insert_project_content` inserts that copy instead of the shorter event, because v4 kept one global row (the longer walk survived) and per-project copies of one event ID must stay equal (`test_tree_events.py` relies on it after Task 8). Covered by `test_every_copy_of_a_tree_walk_keeps_the_longest_state`.
- Task 5 (review fix): `import_package` locked only per project key -> it first takes a global transaction-level advisory lock `_lock_id("import")`, because content identities are global and SQLite's `BEGIN IMMEDIATE` serialised every import; two concurrent imports under different keys could otherwise store conflicting content under one snapshot identity. Covered by `test_imports_of_different_projects_wait_for_each_other`.
- Task 5 (review fix): `tests/test_pg_repository.py` gained top-level imports (`threading`, `ThreadPoolExecutor`, `func`, `key_for`, `SearchEventRecord`, `ValidatedPackage`, `_lock_id`, `SearchEventRow`) -> Task 7 Step 4's replacement import block must keep them.
- Task 6: the appended test block imported `threading` and `ThreadPoolExecutor` with `# noqa: E402` -> those two lines are left out of the block, because Task 5 already imports both at the top of `tests/test_pg_repository.py` and a second import would be a ruff F811 redefinition. The remaining `# noqa: E402` imports (`text`, `DBAPIError`, `RevisionConflict`, `ReviewTargetSet`, `Draft`, `MutationEnvelope`, `Submission`, `WorkspaceKey`) are as planned; Task 7 moves them to the top.
- Task 6: Step 4 expected `15 passed` -> `18 passed`, because Task 5 left 10 test items (the tree-walk test is parametrized and Task 5's review added the import-lock test), plus the 8 new ones.
- Task 6 (review fix): `open_draft` read the draft without a lock -> it takes the same transaction-level advisory draft lock as `run_mutation` (shared helper `_lock_draft`), because under READ COMMITTED a mutation committed between its four SELECTs could give a torn draft (revision N with the content of N+1). Covered by `test_opening_a_draft_waits_for_a_running_mutation`.
- Task 6 (review fix): `_verify_existing_snapshots` read the stored copies of a search event without a row lock -> the select uses `ORDER BY project_id ... FOR UPDATE`, because a concurrent candidate append could otherwise be overwritten by the import's UPDATE (Task 7's `append_search_event_candidates` must lock the row too). Covered by `test_an_import_waits_for_a_writer_of_a_known_search_event`.
- Task 6 (review fix): `_insert_submission` skipped every known submission ID -> it takes `imported: bool` like `_insert_search_event`; only imports use `ON CONFLICT DO NOTHING`, a local submission whose ID is already known in the same project raises `IntegrityError`. Submissions are unique per `(project_id, submission_id)`, so unlike SQLite's global key this does not refuse an ID that only another project knows. Covered by `test_a_local_submission_with_a_known_id_is_refused`.
- Task 6 (review fix): added tests for a rollback of the caller's ambient transaction (draft and receipt undone), the replay of a stored submission, and two concurrent first opens of one draft (one row).
- Task 7: `append_search_event_candidates` locked and updated only the copy in the caller's project (`len(rows) != 1` returned None without a `workspace_key`) -> it locks every copy of the event ID `ORDER BY project_id ... FOR UPDATE` (the order `_verify_existing_snapshots` uses, so no deadlock with an import), checks the copy in the caller's project (or the first copy without a `workspace_key`), and updates all copies by event ID, because every copy of an event ID must stay equal (Task 5/6). The update is by event ID alone so it also reaches a copy that an import, which the append waited for, committed after the append's select. Covered by `test_a_growing_walk_keeps_every_copy_of_its_id_equal`, `test_an_append_waiting_for_an_import_grows_the_new_copy_too` and `test_an_import_waiting_for_an_append_keeps_the_new_terms`.
- Task 7: the appended tests defined a helper `_walk(event_id, key, candidates)` -> named `_project_walk`, because Task 5's `_walk(candidates)` already exists in the file (F811). A helper `_copies` reads every stored copy for the new tests.
- Task 7: the import block of Step 4 dropped Task 5's imports -> the block keeps `func`, `key_for`, `ValidatedPackage`, `_lock_id`, `SearchEventRow` and adds Task 6's late imports (`IntegrityError`, `_key_str`, `DraftRow`, `MutationReceiptRow`); `RevisionConflict` stays because Task 6's tests use it.
- Task 7: Step 5 expected `18 passed` -> `30 passed` (24 before Task 7, the 3 planned tests and 3 for the copy invariant). Full backend suite: 731 passed.
- Task 7 (review fix): `save_search_event` inserted into the caller's project only, so an event ID known in another project was accepted -> it refuses any event ID stored in any project with `DomainError("SEARCH_EVENT_EXISTS", {"event_id": ...})`, because SQLite's global primary key refused it and a growing walk updates every copy of its ID, which would overwrite the other project's different event. SQLite surfaced this as an unhandled `sqlite3.IntegrityError`; no caller catches either error, and legitimate local IDs (uuid4, or `selection-` plus a hash over workspace and mutation) never collide. The check is not locked for the same reason. Imports are unaffected. Covered by `test_a_local_search_event_with_a_known_id_is_refused`.
- Task 7 (review fix): the export's document query had no order -> it orders like `list_documents` (position, nulls last, then document ID). Added `test_an_exported_project_imports_and_exports_unchanged` (export, import under a new key, export again: equal content including imported submissions and search events).
