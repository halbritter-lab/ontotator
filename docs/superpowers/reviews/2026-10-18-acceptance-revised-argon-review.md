#### [High] 1. Re-reviewing an already-accepted translation downgrades the prior variant from `'accepted'` to `'reviewed'`, breaking `require_annotation_gate` (`TRANSLATION_NOT_ACCEPTED`) and distribution eligibility
- **Plan Section:** Technical Contract (`User actions, surfaces and authorities`, [`L115`](../../../docs/superpowers/plans/2026-10-18-acceptance-remediation.md#L115)) and **Task 10: Exact-input work rounds, carry-forward and consolidation** ([`L257-L266`](../../../docs/superpowers/plans/2026-10-18-acceptance-remediation.md#L257-L266)).
- **Verified Source Evidence:**
  - When [`TranslationReviewService.submit`](../../../src/ontocurator/application/translation_reviews.py#L407) runs with `decision == "accepted_with_corrections"`, it sets `next_status = "reviewed"` on the input variant (`variant.document_id`, e.g., v2) and creates v3 with `translation_status = "accepted"` ([`translation_reviews.py`](../../../src/ontocurator/application/translation_reviews.py#L446-L482)).
  - However, [`require_annotation_gate`](../../../src/ontocurator/assignments/eligibility.py#L127-L146) calls [`check_variant_assignable`](../../../src/ontocurator/assignments/eligibility.py#L51-L65), which raises `DomainError("TRANSLATION_NOT_ACCEPTED")` whenever `project["annotate_accepted_translations_only"]` is true and `variant.translation_status != "accepted"`.
  - `require_annotation_gate` is enforced on every non-submitted draft open ([`_before_open_draft` in `scoped.py`](../../../src/ontocurator/authz/scoped.py#L168-L174), [`repository.py`](../../../src/ontocurator/storage/repository.py#L2164-L2169)), every draft/decision/submission mutation ([`_before_new_mutation` in `scoped.py`](../../../src/ontocurator/authz/scoped.py#L180-L188)), every search event ([`save_search_event` in `scoped.py`](../../../src/ontocurator/authz/scoped.py#L738-L742)), and [`AssignmentService.reopen`](../../../src/ontocurator/assignments/service.py#L511-L512). Flipping v2 from `"accepted"` to `"reviewed"` immediately locks out any existing or reopened v2 `WorkRound` with `TRANSLATION_NOT_ACCEPTED`.
  - In addition, [`DistributionDialog.tsx`](../../../frontend/src/admin/DistributionDialog.tsx#L5-L22) also imports [`canReviewSelection`](../../../frontend/src/admin/assignmentUI.tsx#L28-L31), and [`UnassignableDocument.reason`](../../../src/ontocurator/api/assignment_routes.py#L106-L116) / [`AssignmentService`](../../../src/ontocurator/assignments/service.py#L1-L637) use `"translation_already_accepted"`.
- **Remedy:** In the Contract Checkpoint and **Task 10**, define what `TranslationReviewService.submit` sets on an already-accepted source variant when creating v3 (or how `require_annotation_gate` / `WorkflowWarning` treat a previously accepted variant superseded by a newer accepted correction), and include [`src/ontocurator/application/translation_reviews.py`](../../../src/ontocurator/application/translation_reviews.py#L397-L484) and [`frontend/src/admin/DistributionDialog.tsx`](../../../frontend/src/admin/DistributionDialog.tsx#L1-L91) in Task 10's file list.
